# Тест-кейсы «Своё вино»

Автоматические проверки API, каталога и инфраструктурного контракта находятся в `tests/` и запускаются командой:

```powershell
python -m pytest -q
```

## TC-01. Готовность backend

**Предусловие:** backend запущен, модели и индексы загрузились.

**Шаги:** отправить `GET /health`.

**Ожидаемый результат:** HTTP 200, JSON содержит `status: ok` и `ready: true`.

## TC-02. Распознавание корректной фотографии

**Предусловие:** на фото хорошо видна этикетка вина из индекса.

**Шаги:** открыть сканер, выбрать или снять фото, нажать кнопку распознавания.

**Ожидаемый результат:** запрос отправлен как multipart-поле `image`; сервер возвращает HTTP 200, `wine_id` или `slug`, название и список кандидатов; frontend открывает карточку найденного вина.

## TC-03. Вино не найдено

**Предусловие:** используется этикетка, отсутствующая в индексе, либо фото без бутылки.

**Шаги:** загрузить фото и запустить распознавание.

**Ожидаемый результат:** интерфейс показывает состояние «не удалось найти вино», не падает и предлагает повторить фото или перейти в каталог.

## TC-04. Некорректный файл

**Шаги:** отправить в `/predict` текстовый файл под видом изображения.

**Ожидаемый результат:** API возвращает контролируемый ответ об ошибке без traceback и без остановки процесса; следующий корректный запрос продолжает работать.

## TC-05. Запрос без изображения

**Шаги:** отправить `POST /predict` без multipart-поля `image`.

**Ожидаемый результат:** HTTP 400, тело ответа объясняет, что изображение не передано.

## TC-06. Нет обязательного ML-артефакта

**Предусловие:** временно отсутствует один файл из списка `backend-entrypoint.sh`.

**Шаги:** запустить контейнер backend и открыть его logs.

**Ожидаемый результат:** контейнер завершается до запуска API; logs содержат точный путь отсутствующего файла.

## TC-07. Целостность каталога

**Шаги:** запустить `python -m pytest -q tests/test_catalog_contract.py`.

**Ожидаемый результат:** все 2103 slug уникальны, обязательные поля заполнены, локальные изображения существуют, наборы slug frontend/backend совпадают, индексы содержат только позиции каталога.

## TC-08. Отказ в доступе к камере

**Предусловие:** браузер поддерживает камеру.

**Шаги:** запретить сайту доступ к камере и открыть экран сканера.

**Ожидаемый результат:** интерфейс сообщает о недоступности камеры и сохраняет рабочую возможность выбрать фото из файла.

## TC-09. Превышение размера загрузки

**Шаги:** через `/api/scan` отправить файл больше 12 МБ.

**Ожидаемый результат:** Nginx отвечает HTTP 413; frontend показывает понятную ошибку и остаётся доступным.

## TC-10. Маршрутизация через Nginx

**Предусловие:** оба контейнера healthy.

**Шаги:** проверить `/health`, `/api/health`, `/api/wines`, `/api/scan` и неизвестный `/api/example`.

**Ожидаемый результат:** frontend health возвращает 200; backend health доступен через proxy; каталог возвращается в JSON; scan поступает в `/predict`; неизвестный API endpoint возвращает JSON 404, а не HTML приложения.

## TC-11. Позиции без векторного индекса

**Предусловие:** каталог содержит 2103 вина, текущие индексы — 2090 slug.

**Шаги:** открыть карточку одного из 13 вин, отсутствующих в индексах, затем попытаться распознать его фотографию.

**Ожидаемый результат:** карточка доступна из каталога; система не обещает корректное распознавание до пересборки индексов. После пересборки количество индексированных slug должно совпасть с каталогом.
