# Проверка текущего функционала

Запуск из корня проекта. Нужны Python и Node.js 22; Docker для этих тестов не требуется.

```powershell
python -m pip install -r requirements-ci.txt
python -m pytest -q
node --test --experimental-test-isolation=none tests/frontend/*.test.mjs
```

## Что проверяется

- Контракты FastAPI: `/health`, `/wines`, `/wines/{id}` и `/predict`.
- Каталог: уникальные идентификаторы, согласованность CSV, JSON, поисковых индексов и локальных фотографий.
- Полное декодирование фотографий каталога, чтобы выявить повреждённые файлы.
- Инфраструктура: необходимые ML-артефакты и переносы строк скриптов. Для этих проверок нужен `git lfs pull`.
- Интерфейс: поиск, фильтры, пагинация, избранное, история, сравнение, подборки, дневник, паспорт вкуса, сомелье и камера.
- Распознавание: уверенный результат открывает карточку, а неуверенный показывает кандидатов, полученных от ML.
- API-клиент: локальный каталог, `/wines`, `/wines/{id}`, `/predict`, локальные фотографии, multipart-загрузка и обработка ошибок сети.

## Границы проверок

JavaScript-тесты запускают настоящий код приложения в Node VM с заменёнными DOM, камерой, хранилищем и сетью. Они проверяют логику интерфейса, но не заменяют ручную проверку реальной камеры и мобильного браузера.

Python API-тесты заменяют тяжёлый ML-пайплайн. Они не измеряют точность моделей и не подтверждают совместимость весов с установленными версиями библиотек. Для реального прогона нужны скачанные LFS-артефакты, запущенный бэкенд и тестовые фотографии.

Ручные сценарии находятся в [docs/TEST_CASES.md](../docs/TEST_CASES.md).
